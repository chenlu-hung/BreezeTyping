## Overview
BreezeTyping is a macOS Input Method Extension that lets users dictate text into any application by pressing a configurable hotkey. The pipeline is: hotkey press → microphone capture (`Audio`) → on-device Whisper speech-to-text (`Transcription`) → local punctuation restoration (`Punctuation`) → optional LLM correction (`LLM`) → text committed via InputMethodKit (`InputMethod`). UI provides a live status overlay near the cursor and a SwiftUI settings window; configuration is persisted in `UserDefaults` via `Settings`.

## Entry points
- `BreezeTyping/App/main.swift`

## Build / test
Open `BreezeTyping.xcodeproj` in Xcode; build the `BreezeTyping` scheme. The app must be installed as an Input Method (`System Settings → Keyboard → Input Sources`). No automated test suite exists — manual testing in a text editor is required.

## Conventions
- **Concurrency**: long-running work (model loading, audio capture, network) uses Swift structured concurrency (`async/await`, actors). UI updates always dispatched back to `MainActor`.
- **Shared singletons**: `WhisperKitManager.shared`, `PunctuationManager.shared`, `LLMClient.shared`, `AppSettings.shared` — all consumed by `BreezeTypingInputController`.
- **Optional pipeline stages fail open**: punctuation and LLM correction both return the text they were given if their model or endpoint is unavailable, so a stage that breaks costs formatting, never the dictation.
- **InputMethodKit registration**: `@objc(BreezeTypingInputController)` class name must match the `InputMethodConnectionName` key in `Info.plist`; changing either breaks IMK registration.
- **Silence threshold**: auto-stop fires from `SilenceDetector` via a callback into `AudioRecorder.startRecording(onSilenceDetected:)`, then marshalled to `DispatchQueue.main` by the caller in `InputMethod`.
